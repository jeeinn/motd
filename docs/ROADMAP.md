# Roadmap — motd 后续路线图

> 维护约定：只记「已评估、待实施」的方向与决策依据，不记已完成项（那在 CHANGELOG/DECISIONS）。
> 每条带「状态 / 触发条件 / 估工 / 风险」，供拍板时快速取舍。

## R-01 终端多色扩展（含节日主题彩蛋）

**状态**：已评估，待拍板。用户 2026-11-21 提出，起因是当前终端"只有黑白灰"，希望支持更多颜色以便后期拓展（如特殊节日）。

### 现状核实（代码事实）

- `internal/presentation/terminal/safe/ansi.go` 的 `Style` 枚举有 7 项：Plain / Bold / Dim / Italic / Code / Link / Header。
- 其中**只有 `StyleCode` 带颜色**（青色 `\x1b[36m`），其余是字重/下划线/暗色。用户体感"黑白灰"基本准确。
- 安全边界：所有 ESC 序列只允许来自 `ansi.go` 的常量表，`archtest` 扫描全包 + 负向注入测试守门（ED 清屏/CUP 定位/OSC/非数字参数全部禁止）。
- 用户内容走 `RenderUser` → `SanitizeText`（ESC 转可见图示）→ 白名单 Markdown → SGR；服务端文本走 `RenderSystem`。两条路径共用同一个 SGR 常量表。

### 技术评估

| 维度 | 结论 |
|---|---|
| 实现成本 | **低**。在 `ansi.go` 的 `Style` 加枚举值（如 StyleRed/Green/Yellow/Blue/Magenta）+ SGR 常量（31–37 / 90–97），`openANSI/closeANSI` 补分支即可。archtest 自动覆盖新常量，无需改守门逻辑。 |
| 安全风险 | **低**。新增序列仍是 SGR（只改颜色，不动光标/不清屏/不写剪贴板），在白名单类别内；不扩大信任域，用户内容依旧无法选择颜色。 |
| 终端兼容 | 中。基础 8 色（30–37/90–97）几乎所有 ANSI 终端支持；256 色（38;5;n）与真彩（38;2;r;g;b）在部分终端/复用器（tmux/screen）需额外配置。建议**只用基础 8/16 色**，不上 256/真彩。 |
| 可读性风险 | 中。深浅色背景终端的对比度不同；红/绿对红绿色盲不友好。需要配套规则：颜色只作辅佐信息，**不单独承载语义**（与状态栏 Notice 用文字分类同理），并避免纯红/绿表意。 |
| 测试成本 | 低。现有 `render_test.go`/`samples_test.go` 加几个断言；archtest 负向注入自动生效。 |

### 建议实施顺序（拍板后）

1. **基础配色**：新增 8 色 Style + 用在新场景：等级分档（L2/L3/L4 不同色）、错误/成功状态提示、版块名着色。
2. **节日主题**（用户举例）：在固定日期窗口（如 12/25、1/1、春节）给欢迎页/状态栏换配色，纯服务端固定文案 + 白名单 SGR，不接用户输入。以「可关闭配置」为前置（新增 `MOTD_THEME=auto|off`），避免用户被迫接受。
3. **进阶（不推荐近期做）**：256 色/真彩、用户自定义配色（会引入配置面与终端探测复杂度）。

### 触发条件与估工

- 基础配色：约半天，零迁移、零新依赖，风险低。
- 节日主题：约 1 天（含日期窗口逻辑与配置），需明确"哪个节日用什么色"的产品决策。
- 前置：用户明确"上哪些颜色 + 用在哪些元素 + 是否可关闭"。

## R-02 已延后彩蛋（v0.6.0 未纳入）

三项原本排在 P3-M6、因风险/成本延后，保留备选：

| 项 | 延后原因 | 前置条件 |
|---|---|---|
| 动态 `/matrix` 全屏雨 | ADR-027 禁止 ED 清屏 / CUP 定位 / 备用屏，真全屏动画需扩白名单，风险高 | 单独评估"专用动画渲染通道"与信任域边界；v0.6.0 已做合规的滚动雨帘版本 |
| 连续签到里程碑扩展（30/100 天） | 需更多成就码与展示位 | 当前 7 天里程碑已落地，观察用户反馈再定 |
| 更多隐藏版块 | 目前只有 /dev/null（按用户解锁） | 需产品层面定义"隐藏什么、怎么解锁" |

## R-03 容量与压测（延续 P3-M4 诚实口径）

- 当前最小压测集给的是回环环境相对延迟基线，**不构成 1 Mbps / 1000 在线验收证据**。
- 目标机器与真实网络下的 100/300/500/1000 分档实测仍未做；提升 MaxConns 后的行为未验证。
- 触发条件：有明确的目标机器规格与网络环境后再排期。
