## 2. 逐项详情

### R-06 详情屏内容分页（**已发布 v0.9.1**）

- **落地**：v0.9.1 已发版（ADR-073）。方案见 [`docs/DESIGN-detail-pagination.md`](DESIGN-detail-pagination.md)。采用**整块装箱分页**——正文按物理行切、回复按整条装，`n`/`p` 统一表示"往下/往上读一页"（无新键位），每页 `终端高度 - 7 - 帖子标题行数` 行且回复不超过 20 条；回复后走末页 Tail 查询恢复 ADR-068 焦点锚定。核心证据：数据层 keyset 已就绪、渲染层已在显示"按 n"、键位层却对详情屏空转；回复后的焦点回填代码已自认"超 200 条回退首行"。
- **问题**：详情屏一次渲染整帖全部回复，上限 `MaxPostsPerThread = 200`（`internal/application/forum/validate.go:18`，注释原文即"P1 再做内容分页"）。超过 200 条回复时**新回复不可见**，用户会以为没发出去；且详情屏内 `n` / `p` 翻页键无效（只在列表页生效）。
- **影响面**：长主题（技术长贴、争议帖）的核心阅读与追更体验。**用户 2026-11-24 判定属功能性缺口（内容不可达），非体验优化，故定 P0。**
- **方案方向**：把列表页的 `n`/`p` 语义扩展到详情（不做自由滚动——终端无鼠标，键盘分页更可控）；每页都带 footer 与状态栏；跨页焦点按 `Row.ID` 回填（ADR-066/ADR-068）；查询改成 Limit/Offset 并强制走索引。
- **优先级定案**：设计稿原评 **P1**、`ADR-072` 代价段称"独立 **P0** 项"，两者本不一致；本次按 **P0** 统一（`ADR-072` 的 P0 口径为准，设计稿 P1 评级作废）。不与其他项搭车：它同时动查询/焦点/渲染三条链，回归面大于此前任一单点修复。
- **风险**：同时触碰查询、焦点、渲染三条链，回归面大于此前任何一个单点修复；需虚拟网格 + 真实 SSH 双验证。

### R-07 草稿持久化落库

- **现状**：草稿只在**会话内**保留（ADR-067），断连即丢。
- **目标**：`drafts` 表 + TTL 清理 + 写队列，支持断连/重登恢复。
- **前置**：另立 ADR 评估与 ADR-010（单写连接）的背压关系，不能把草稿写入塞进业务事务。
- **估工** M（一次迁移 + 写队列 + 恢复路径）。

### R-08 全量 UI 文案 i18n

- **现状**：i18n 只覆盖 10 个 hint key 与 notice 前缀（`internal/presentation/terminal/i18n/catalog.go`），默认 zh 逐字节不变（ADR-070）。
- **缺口**：状态栏、footer、命令回显、错误文案、`/help` 分组标题仍是硬编码中文。
- **风险**：文案量大且散落在渲染层与命令层；需先定"哪些文案进 catalog、哪些保持硬编码"的边界，否则会变成字符串搬家。

### R-09 resize 即时对齐（**已实施，待随下版发布**）

- **原问题**：终端缩放后若用户不按键，当前屏仍是旧宽度排版的字节、由终端自行重排，**下一次 `render()` 才对齐**（ADR-072 边界 2；ADR-071 代价 2 同源）。
- **落地（ADR-074）**：transport 在 `window-change` 且尺寸真变化时非阻塞投递一条通知（`Session.ResizeNotify()`，容量 1、永不关闭）；`inputHandler.Serve` 主循环收到后自行调 `pc.render(sess)` 按新宽高整屏重绘当前屏，不再等下一次按键。
- **分层约束**：transport 只投信号、**绝不直接 Write 终端**——页面状态归 handler goroutine，直接写会与按键回显字节交错并构成状态竞态；`pageSession` 接口零改动，依赖方向与 archtest 守卫不变。
- **不做什么**：不调 `pc.refresh()`（会把详情页踢回第 1 页并重查库）；命令输入 / 编辑器 / 登录 / 邮箱交互态跳过重绘（逐字节追加回显会被 `H+2J` 抹掉）。详情页 resize 只重绘当前已装箱的一页，不重算分页装箱，按 `n`/`p` 后即按新容量重排。
- **验证**：transport 通知语义 + 真实 SSH `window-change` 端到端；`resizeRedrawable` 6 项表驱动 + 真实 SSH 重绘闭环（含交互态跳过 / 恢复）。四门禁 + 两闭环全绿，测试函数 1114 → 1119。
- **状态**：代码已本地提交（`5a31ea4`），**未 push / 未发版**；线上 VPS 仍为 v0.9.0。

### R-11 节日主题彩蛋（原 R-01 剩余项）

- **已完成部分**：基础多色（`StyleBold/Dim` + `accent/notice/error` 三色）随 v0.7.0 发版，`archtest/color_test.go` 守门。
- **剩余**：固定日期窗口（12/25、1/1、春节）给欢迎页/状态栏换配色。纯服务端固定文案 + 白名单 SGR，不接用户输入。
- **前置**：必须可关闭（`MOTD_THEME=auto|off`），避免用户被迫接受。
- **明确不做**：256 色 / 真彩（tmux/screen 需额外配置）、用户自定义配色（引入配置面与终端探测复杂度）。

### R-10 差异行增量渲染

- **现状**：每帧重发整屏字节（视觉上只有一屏），未做差异行优化。
- **背景**：ADR-027 曾按 FF09 延后，理由是"属浏览器端 Frame 增量同源能力，不提前引入"。
- **结论**：**不建议单独做**，与 R-04 的 Frame 增量协议一起设计——同一套 diff 语义服务两端，避免做两遍。

### R-04 浏览器端 TUI 帧传输（P5 主线）

**状态**：方向已定（用户 2026-11-21 拍板为 P5 主线），**未开工，开工前需新 ADR**。这是对既有冻结口径（`archived/P3-PLAN.md` §8 / `archived/PHASE1-PLAN.md` §1.2）的正式解禁。

**方案**：服务端渲染语义 Frame + 本地键盘渲染器，与终端共用 ViewModel、独立渲染；Frame 增量 ops（upsert/remove/move/overlay/focus）+ seq/base_seq 恢复；不采用 xterm.js，JS ≤15 KB gzip。

**现状（代码事实）**：`internal/transport/websocket/doc.go`、`internal/presentation/browser/doc.go` 各 3 行纯占位——从零建，非续写。

**风险 / 前置**：

- 重议触发条件（`archived/P2-PLAN.md`）为"1000 在线压测通过 + 契约进 1.0"，**当前一条不满足**；用户拍板属产品层强制解禁，需在开工前正面处理"无容量背书下开新公网入口"。
- 0.x 对外契约一旦上线即焊死；容量 1 Mbps / 1000 在线未验收（ADR-059、R-03）。
- 安全边界：浏览器端用 `textContent`，与终端 `RenderSystem`/`RenderUser` 同等严格；WebSocket 校验 `Origin`，不依赖 `SameSite=Lax`。
- 量级 L，多模块；新 ADR 从 **ADR-076** 顺延（解禁决策 + Frame 协议 + Origin 校验 + 双端安全边界）。
- 容量验收是否作为 P5 硬前置，需用户再拍板。

### R-03 容量与压测

- 当前最小压测集给的是回环环境相对延迟基线，**不构成 1 Mbps / 1000 在线验收证据**。
- 目标机器与真实网络下的 100/300/500/1000 分档实测仍未做；提升 MaxConns 后的行为未验证。
- 触发条件：有明确的目标机器规格与网络环境后再排期。
- 注：v0.9.0 的整屏重绘已把帧开销压到 **310–414 B/帧**（实测），比传统网页低 2~4 个数量级，但这是单帧量级事实，不等于并发容量结论。

### R-12 / R-13 小项

- **R-12 签到里程碑**：现只有 7 天成就；30/100 天需新成就码与展示位，观察现有反馈再定。
- **R-13 更多隐藏版块**：目前只有 `/dev/null`（按用户解锁）；需产品层面定义"隐藏什么、怎么解锁"。

## 4. 已评估、明确不做

| 项 | 理由 |
| --- | --- |
| 状态栏物理钉底 | ADR-071 代价 3 评估：把内容撑到终端高度会让光标重新落到底行，收益不明确；当前"状态栏跟随内容"已满足可读性 |
| 256 色 / 真彩 | tmux/screen 需额外配置，基础 8/16 色已够表意 |
| 用户自定义配色 | 引入配置面与终端探测复杂度，且颜色不得单独承载语义 |
| @提及与未读 | `mentions` 表不存在、`RowMeta.Unread` 从不赋值；需推翻 R11 + 新 ADR + 触显示契约 |
| 节点移动 / 合并 | 需快照 + dry-run + kill-9/WAL 演练级门槛；当前 5 个 seed 版块无痛点 |
| 分权 / role / RBAC | 已明确否决；白名单 + 作者权两点足够 |
| Passkey / WebAuthn | 设计稿列 P2 增强，无真实需求证据 |
| RSS / 只读 API / JSON 输出 / AI 摘要 / 原生 CLI token / 主题 ASCII Art | 0.x 对外契约冻结；留存价值未验证 |
| 彩蛋自定义 / 用户输入参与文案 | 违反零回显与安全渲染原则（`eggs.md` §8） |
