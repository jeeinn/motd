# Roadmap — motd 后续路线图

> 维护约定：只记「已评估、待实施」的方向与决策依据，不记已完成项（那在 CHANGELOG/DECISIONS）。
> 每条带「状态 / 触发条件 / 估工 / 风险」，供拍板时快速取舍。
> **中期路线图（用户 2026-11-21 拍板，2026-11-22 补充）**：P4 = 可靠性收尾 + 基础多色（已发 v0.7.0，详见 `docs/P4-PLAN.md`）；**P4.5 = 运营可见性（`/latest` + `/stats`，用户反馈触发，详见 `docs/P4.5-PLAN.md`，目标 v0.7.1）**；P5 = 浏览器端 TUI 帧传输（见 R-04）；其余个性化/运营扩展按未来用户反馈再排期。

## R-04 浏览器端 TUI 帧传输（P5 主线）

**状态**：**方向已定（用户 2026-11-21 拍板为 P5 主线），未开工，开工前需新 ADR**。这是对既有冻结口径（P3-PLAN §8 / PHASE1-PLAN §1.2）的正式解禁。
**方案**：服务端渲染语义 Frame + 本地键盘渲染器，与终端共用 ViewModel、独立渲染；Frame 增量 ops（upsert/remove/move/overlay/focus）+ seq/base_seq 恢复；不采用 xterm.js，JS ≤15 KB gzip（设计稿 §3.2/§3.3）。
**现状（代码事实）**：`internal/transport/websocket/doc.go`、`internal/presentation/browser/doc.go` 各 3 行纯占位——从零建，非续写。
**风险 / 前置**：
- 重议触发条件（P2-PLAN:164-170）为"1000 在线压测通过 + 契约进 1.0"，**当前一条不满足**；用户拍板属产品层强制解禁，需在 P5 开工前正面处理"无容量背书下开新公网入口"。
- 0.x 对外契约一旦上线即焊死；容量 1 Mbps / 1000 在线未验收（ADR-059、R-03）。
- 安全边界：浏览器端用 `textContent`，与终端 `RenderSystem`/`RenderUser` 同等严格；WebSocket 校验 `Origin`，不依赖 `SameSite=Lax`（设计稿 §3.5:390、§3.2:326）。
- 量级 L，多模块；新 ADR 从 ADR-063 顺延（解禁决策 + Frame 协议 + Origin 校验 + 双端安全边界）。
- 容量验收是否作为 P5 硬前置，需用户再拍板。

## R-01 终端多色扩展（含节日主题彩蛋）

**状态**：**基础多色已纳入 P4（用户 2026-11-21 拍板，详见 `docs/P4-PLAN.md` P4-T1），待开工**；节日主题按同一拍板推未来、按用户反馈再排期。用户提出起因是当前终端"只有黑白灰"。

### 现状核实（代码事实）

- `internal/presentation/terminal/safe/ansi.go` 的 `Style` 枚举有 7 项：Plain / Bold / Dim / Italic / Code / Link / Header。
- 其中**只有 `StyleCode` 带颜色**（青色 `\x1b[36m`），其余是字重/下划线/暗色。用户体感"黑白灰"基本准确。
- 安全边界：所有 ESC 序列只允许来自 `ansi.go` 的常量表，`archtest` 扫描全包 + 负向注入测试守门（ED 清屏/CUP 定位/OSC/非数字参数全部禁止）。
- 用户内容走 `RenderUser` → `SanitizeText`（ESC 转可见图示）→ 白名单 Markdown → SGR；服务端文本走 `RenderSystem`。两条路径共用同一个 SGR 常量表。

### 技术评估

| 维度 | 结论 |
|---|---|
| 实现成本 | **低**。在 `ansi.go` 的 `Style` 加枚举值（如 StyleRed/Green/Yellow/Blue/Magenta）+ SGR 常量（31–37 / 90–97），`openANSI/closeANSI` 补分支即可。archtest 自动覆盖新常量，无需改守门逻辑。 |
| 安全风险 | **低**。新增序列仍是 SGR（只改颜色，不动光标/不清屏/不写剪贴板），在白名单类别内；不扩大信任域，用户内容依旧无法选择颜色。 |
| 终端兼容 | 中。基础 8 色（30–37/90–97）几乎所有 ANSI 终端支持；256 色（38;5;n）与真彩（38;2;r;g;b）在部分终端/复用器（tmux/screen）需额外配置。建议**只用基础 8/16 色**，不上 256/真彩。 |
| 可读性风险 | 中。深浅色背景终端的对比度不同；红/绿对红绿色盲不友好。需要配套规则：颜色只作辅佐信息，**不单独承载语义**（与状态栏 Notice 用文字分类同理），并避免纯红/绿表意。 |
| 测试成本 | 低。现有 `render_test.go`/`samples_test.go` 加几个断言；archtest 负向注入自动生效。 |

### 建议实施顺序（拍板后）

1. **基础配色**：新增 8 色 Style + 用在新场景：等级分档（L2/L3/L4 不同色）、错误/成功状态提示、版块名着色。
2. **节日主题**（用户举例）：在固定日期窗口（如 12/25、1/1、春节）给欢迎页/状态栏换配色，纯服务端固定文案 + 白名单 SGR，不接用户输入。以「可关闭配置」为前置（新增 `MOTD_THEME=auto|off`），避免用户被迫接受。
3. **进阶（不推荐近期做）**：256 色/真彩、用户自定义配色（会引入配置面与终端探测复杂度）。

### 触发条件与估工

- 基础配色：约半天，零迁移、零新依赖，风险低。
- 节日主题：约 1 天（含日期窗口逻辑与配置），需明确"哪个节日用什么色"的产品决策。
- 前置：用户明确"上哪些颜色 + 用在哪些元素 + 是否可关闭"。

## R-02 已延后彩蛋（v0.6.0 未纳入）

三项原本排在 P3-M6、因风险/成本延后，保留备选：

| 项 | 延后原因 | 前置条件 |
|---|---|---|
| 动态 `/matrix` 全屏雨 | ADR-027 禁止 ED 清屏 / CUP 定位 / 备用屏，真全屏动画需扩白名单，风险高 | 单独评估"专用动画渲染通道"与信任域边界；v0.6.0 已做合规的滚动雨帘版本 |
| 连续签到里程碑扩展（30/100 天） | 需更多成就码与展示位 | 当前 7 天里程碑已落地，观察用户反馈再定 |
| 更多隐藏版块 | 目前只有 /dev/null（按用户解锁） | 需产品层面定义"隐藏什么、怎么解锁" |

## R-03 容量与压测（延续 P3-M4 诚实口径）

- 当前最小压测集给的是回环环境相对延迟基线，**不构成 1 Mbps / 1000 在线验收证据**。
- 目标机器与真实网络下的 100/300/500/1000 分档实测仍未做；提升 MaxConns 后的行为未验证。
- 触发条件：有明确的目标机器规格与网络环境后再排期。

## R-05 运营可见性扩展（P4.5，目标 v0.7.1）

**状态**：**已实现，待发版 v0.7.1（用户 2026-11-22 拍板，同日实施）**，完整方案、口径与实施期修订见 `docs/P4.5-PLAN.md`（ADR-063 / ADR-064）。这是 P4-PLAN §3 预留的「运营扩展按真实用户反馈再排期」的首次兑现——已部署实例（jeeinn.com）的实际使用反馈触发。

两项内容：

- **`/latest` 跨版块最新动态**：全论坛最新主题列表（活跃度排序，新回复自动置顶），导航复用现有 ScreenThreads 链路，解决「必须逐版块翻找最新帖」的痛点。可见性与版块列表一致（含该用户已解锁的隐藏版块），查询用显式白名单 + 强制索引。
- **`/stats` 社区看板**：今日/昨日登录人数（`daily_checkins`）、今日/昨日峰值在线与历史最高在线（新 `stats_daily` 表 + cmd 层 30s 采集）、注册用户数、累计登录人次（新 `login_success` 审计事件）。

关键口径：登录人次只计主动登录动作（GitHub Device Flow / 邮箱密码），重连公钥恢复不计；统计起点诚实标注（登录 v0.6.0 起、峰值与累计登录 v0.7.1 起），零回填零臆造。

风险与估工：S~M（合计约 2~2.5 天），一次迁移（0011：索引 ×2 + `stats_daily` 表），零新依赖、零新环境变量、零新入口。
