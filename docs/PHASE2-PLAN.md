## 1. v0.2.1 —— 低风险补齐

### 1.1 标题/正文虚线分隔

- **位置**：`internal/presentation/terminal/view.go` 详情屏，`ext(Title)` 与 `ext(Body)` 之间插入一条 `sys(&b, "──", safe.StyleDim)` + 换行，与下方「── 回复 ──」上下对称。
- **归属**：纯呈现层固定文案，走 `RenderSystem` 路径；零用户内容、零光标控制，不碰 ADR-019 / ADR-027，archtest 守卫不受影响。
- **不选 `#` 的理由**：标题走 `ext(RenderUser)`，而安全白名单的 Markdown 不支持 heading，改 `ext` 语义会污染全屏所有标题。
- **成本**：约 1 行改动，不动 viewmodel / cmd。

### 1.2 作者删除自己的主题/回复

- **所有权**：只有作者本人能删自己发的主题与回复，规则集中在一处 `canModify(user, entity)`（`entity.UserID == currentUser.ID`）。访客只读，天然排除。
- **命令**：`/delete <id>`（默认作用于当前打开的主题/回复）；非作者返回统一提示「仅作者可删除」，不泄露内容是否存在（延续 `/keys` 防指纹枚举口径）。
- **删除语义**：**软删不硬删**——仅置 `status=deleted`，不级联硬删回复；有回复的主题被删时回复行保留（护住引用完整性），随主题一并不可见。
- **无硬前置**：`threads.status` / `posts.status` / `UserID` 均已在，不需新字段、新状态、新迁移。
- **非目标**：富文本、版本历史、审核流、硬删、他人内容删除、管理员/版主删帖、编辑功能、被删内容的公开恢复入口。
- **后续扩展**：`status` 已有 `hidden` 值，将来引入版主时可复用为治理位，所有权判断只在 `canModify` 一处加 `author OR moderator` 分支。

**验收标准**：
1. 登录作者 A 发主题 T，执行 `/delete T` → T 的 `status=deleted`，T 及下属回复在列表/详情不可见，但回复行仍在库中。
2. 非作者 B 或访客对 T 执行 `/delete` → 被拒并提示「仅作者可删除」，数据零变更。
3. 已被软删的 T 经 `open` / `search` 直接访问 → 返回「内容不存在」，无状态泄漏。

## 2. v0.3.0 —— 邮箱 + 交互改进

### 2.1 邮箱注册/登录/密码找回（既定，L 体量）

自带 163 SMTP、配置放 `.env`、开放公开注册 + IP/邮箱双限流。详见 `docs/PHASE1-PLAN.md §2.9` 与 `.env.sample` 预留段。

### 2.2 跨行退格合并 + 行内左右移动（方案 B 收窄版）

**v0.3.0 进度**：跨行退格合并 ✅ 已完成（2026-11-19，测试 661）。行内左右移动本版不做。

**技术裁定（勿推翻）**：方向键在输入侧完全可用（`decoder.go` 已把 CSI `ESC[A-D` 与 SS3 两种形式提升为 `KeyArrow*`），真正的限制在输出侧——ADR-027 白名单只放开 SGR + EL + CUU，明禁 CUP(H/f)/CUD(B)。**不放宽白名单**：放宽等于把「用户内容永不触达光标控制」从白名单物理隔离退化成靠纪律约束，不划算。

- **实现路径**：composer 维护逻辑光标（line/col）+ 当前行整行重绘（CUU 回车首 + EL 清行 + SGR 反显标光标位置重写该行），全程只用白名单内序列；跨行退格 = 本行删空后并入上一行末尾再整行重绘。
- **若排期紧**：先只做「跨行退格合并」——直击真实痛点，比整条方向键链路更省更准。
- **不排期**：全功能多行编辑（跨行光标、任意位置插入）属方案 C，须新开 ADR 单独论证放宽白名单的安全面，禁止顺手放开 CUP/CUD。

**已知边界**：孤立 ESC 的 25ms 决策窗口（跨包抖动 >25ms 会误判为独立 Esc）；根治靠 kitty keyboard protocol，不在本阶段。

## 3. 编辑功能（v0.3.0 之后）

**用户已定策略：已编辑标记。** 保留原投票与回复，内容旁显示「已编辑」+ 时间——保留历史脉络、实现相对简单，接受"投票对象可能是改前内容"的语义代价。

**硬前置（缺一不可）**：
1. 新增 `edited_at` 字段并迁移；
2. 已编辑标记的展示口径（内容旁固定文案 + 服务端格式化时间，走 `RenderSystem` 固定路径，不进用户内容净化链）。

**范围边界**：编辑仅作者本人可操作，复用 `canModify`；不做富文本、版本历史/diff、审核流。打开前需确认 `edited_at` 展示是否影响现有 `ViewItem` 结构（触及显示契约，需按 ADR-014 三层守卫评估）。
