## 3. M2：`/latest` 跨版块最新列表（先行）

### 3.1 设计

**`/latest` = 「全部版块的主题列表屏」**。不新增页面类型：导航（j/k/Enter/q/n/p）、翻页游标、打开详情、返回位置保持、`/top` 一律回版块列表——全部免费复用现有 `ScreenThreads` 链路；`/help` 自动收录（命令表是唯一入口）。

| 层 | 改动 | 说明 |
| --- | --- | --- |
| 仓储 | `ThreadQuery.NodeID == 0` = 跨版块，且**必须**同时给出 `AllowedNodeIDs`：`SELECT t.id, t.node_id, … FROM threads t INDEXED BY idx_threads_last_reply WHERE t.status = 'active' AND t.node_id IN (?,…)`，游标用**行值比较** `AND (t.last_reply_at, t.id) < (?, ?)`，多取一条判 hasMore；白名单为空时 fail-closed 返回空页 | 版块内分支（`NodeID > 0`）SQL **逐字不动**。禁止写 `JOIN nodes … status='active'`（会挡掉已解锁 `/dev/null`），也禁止放宽成「archived 也可」；可见性只由白名单决定。列投影必须逐列书写，**不能 `SELECT t.*`**（threads 自 0004 起 8 列，`scanThread` 只扫 7 列，运行期报错） |
| 索引 | 迁移 0011：`CREATE INDEX idx_threads_last_reply ON threads(last_reply_at DESC, id DESC)`；查询侧 **`INDEXED BY` 强制命中** | 实测：不加提示时同一句 SQL 在不同数据分布下会选 `idx_threads_node` + `USE TEMP B-TREE`，索引断言不可稳定复现；强制后计划恒为 `SEARCH t USING INDEX idx_threads_last_reply` 无 temp 排序，缺索引则在 prepare 期 fail-fast。行值游标把深翻页从 O(k×N) 降到 O(N)（首屏无差别） |
| 用例 | `Service.ListThreads` 接受 `NodeID == 0`；`NodeID < 0` 返回 `ErrInvalidNodeID`（用例层单点校验，仓储保留同款防御） | `service.go:152-184`、`ports.go:48-62`。`ThreadCursor` 编码不变，行值只改 SQL 形态，上层零契约变更 |
| ViewModel | `ScreenThreads` 在 `q.NodeID == 0` 时：一次 `ListNodes`（active）∪ `ViewContext.UnlockedHiddenNodes` 算出白名单并发给仓储，同时建 `id→slug` 映射填充各行 `RowMeta.Node`；`NodeID > 0` 时**不填** | 白名单是**放行**语义而非排除语义，因此已解锁的 `/dev/null`（`status='archived'`）能正常出现在 `/latest`。slug 走 `ext()` 净化链（管理员文本，与版块列表屏同口径） |
| 命令 | `defaultCommands` 加 `{Name: "latest", Usage: "/latest", Summary: "全论坛最新主题（跨版块）", MaxArgs: 0}`（放 search 附近） | 命令表唯一入口；自动进 `/help` |
| 页面 | `pc.command` 加 `case "latest": return p.showThreads(ctx, sess, 0, latestScope, "", 0)`；`latestScope = "latest"` 是固定串常量 | `nodeSlug` 必须以 `/` 开头（`ValidateSlug`），故 `latest` 不可能与真实版块冲突。详情页 `back()` 用 `p.nodeID/p.nodeSlug/p.cursor/p.offset` 原样回到 `/latest` |
| 输入 | 无改动 | `/latest` 是页面命令，走 `handle` 的 default 分支 → `pc.command`（现状核实 #7） |

### 3.1.1 同屏上下文的三处修正（实测发现，M2 内一并修）

| 现象 | 修法 |
| --- | --- |
| 进入版块/切到 `/latest` 的**首帧**状态栏「位置」显示上一屏（`viewContext` 读的是控制器旧字段） | `showThreads` 里 `if slug != "" { v.Context = slug }` |
| 检索结果 → 详情 → `q`：`nodeID=0, nodeSlug=""` 的残缺态会落到空主题列表 | `showThreads` 开头：`nodeID == 0 && slug == ""` 直接 `showNodes` |
| `p.offset` 从检索屏带过来，跨版块首屏行号从 21 起 | `cursor == ""` 时 `offset = 0` |

**明确不做（M2 范围内）**：`SortScore` 跨版块热度榜（未来可加，本次只做 `SortLatest`）；标题/摘要差异着色（遵守「颜色不单独承载语义」）；新回复/新主题的文字区分标记（`LastReplyAt` 与 `CreatedAt` 已在 Meta，渲染层增强留待反馈）。

### 3.2 DoD

> **修订（2026-11-22 团队裁决）**：原第 1 条写「归档版块主题不出现（含 `/dev/null`）」——**方向是反的**。
> `/dev/null` 是 `status='archived'` 的**彩蛋版块**，不是被归档的普通版块；它的可见性由
> `user_node_unlocks` 按用户决定，用户能在版块列表点进去读，其主题就必须出现在「全论坛最新」里，
> 否则命令名义跨版块、实际悄悄丢掉用户有权看的那一块。**改判据不改实现的理由**：若照原 DoD 验收，
> 正确实现会被判不合规，而「修」成符合原 DoD 的做法恰好是回归。

1. **可见性三态**（逐行全等断言，不只断条数）：
   - 访客 / 未解锁用户：只见公开 active 版块的主题；管理员归档的**普通**版块不出现；`/dev/null` 不出现；
   - 已解锁 `/dev/null` 的用户：= 前者 + 该版块的主题（其余行顺序不变），行内带 `/dev/null` slug；
   - 管理员归档的非彩蛋版块：**三种身份下都不得出现**（防「放宽成 status OR」的护栏）。
2. 排序与分页：`last_reply_at DESC, id DESC`、软删过滤、keyset 翻页（**同秒多帖不重不漏**，翻页并集 = 全量）、hasMore 边界——repo 集成测试覆盖；
3. 版块内列表行为零变化（既有 `repo_forum_test.go` / `service_test.go` / `forum_integration_test.go` 全量回归通过）；
4. `ScreenThreads` 跨版块行含版块 slug、`@作者`、`rN`（投影复用）；版块内屏**不含** slug（现状断言不破）；
5. `/latest` 导航闭环：任意屏 `/latest` 进入（首帧状态栏即显示 `latest`）→ Enter 开主题 → `q` 回 `/latest`（保持游标位置）→ `n` 翻页 → `/top` 回版块列表；`/latest` 上 `/new` 给出「请先进入一个版块再发新主题」固定提示；
6. 命令注册表含 `latest`；`/help` 输出同步；固定文案断言同步更新；
7. **执行计划**：跨版块查询含 `USING INDEX idx_threads_last_reply`、**不含** `USE TEMP B-TREE FOR ORDER BY`，ANALYZE 前后一致；断言只看 `detail` 列、禁止字符串全等（`id/parent` 每次不同）；缺索引时 prepare 期报错（fail-fast，不静默退化）；
8. archtest 全绿（无新端口、无依赖方向变化）；**新增的查询契约需登记**：`ListThreadsQuery/ThreadQuery.AllowedNodeIDs`（不是 ViewModel 契约）、`ErrInvalidNodeID`；
9. ADR-063：跨版块列表决策（`NodeID=0` 语义、allow-list 可见性口径与「不得放宽 status」、活跃度排序、强制索引 + 行值游标、slug 投影、空态与假 slug 的取舍）。

## 4. M1：`/stats` 社区统计看板

### 4.1 统计口径（用户 2026-11-22 拍板）

| 指标 | 口径 | 数据源 | 起点声明 |
| --- | --- | --- | --- |
| 今日/昨日登录人数 | 当日登录去重人数（幂等签到行数） | `daily_checkins` COUNT（按 `local_date`，`MOTD_DISPLAY_TIMEZONE`） | v0.6.0 起已有真实数据 |
| 今日在线人数 | 当日**峰值**在线（30 秒采样，可能低估瞬时尖峰） | `stats_daily.peak_online`（新表） | 自 v0.7.1 起累积 |
| 昨日在线人数 | 昨日峰值在线 | 同上 | 同上 |
| 历史在线峰值 | 跨进程全局峰值 | `MAX(peak_online)` | 同上 |
| 当前在线（活跃） | 实时连接数（活跃数） | `presence.Online()/Active()`（内存） | 实时 |
| 注册总人数 | 累计注册用户数 | `users` `COUNT(status='active')`（deleted/deleting 不计，防注销虚增） | 全历史 |
| 累计登录人次 | 历史累计**登录动作**成功次数 | `auth_events` `COUNT(event='login_success')`（新事件） | 自 v0.7.1 起累积 |

**观测态（`observed`）语义**：两个峰值类指标必须能表达「没有观测」——`stats_daily` 无该日行即
`observed=false`，渲染为 `--`；而**渲染时刻的实时在线数本身也是一次观测**，因此
`今日在线峰值` 显示 `--` 当且仅当「该日无行 **且** 当前在线为 0」。计数类指标（登录人数/注册数/
累计登录）没有 `observed` 概念：0 就是真的 0。展示层另做两处自洽钳制：今日 = max(库值, 当前在线)；
历史 = max(全时 MAX, 今日显示值)——由此恒有「历史 ≥ 今日 ≥ 当前在线」。

**login_success 事件语义**：一次「登录动作」成功 = GitHub Device Flow 授权完成登录/建号，或邮箱密码登录成功（即 `UpgradeToUser` 成功，现状核实 #10 的两个 `onLogin` 调用点）。**重连凭公钥恢复登录态不计**——那是会话恢复不是登录动作，避免频繁断线重连灌水人次。

### 4.2 login_success 埋点（改 onLogin 签名）

> **修订（2026-11-22 团队裁决）**：原稿写 `gate.Record(AuditLoginSuccess, userID, provider, "", "")`，
> 但 `SecurityGate` 只有**未导出**的 `record()`，且它固定用 `g.provider`（装配时恒为 `github`）——
> 邮箱登录会被记成 github。改为新增导出方法，显式接收 provider。

1. `onLogin` 钩子签名 `func(ctx, userID)` → `func(ctx, userID int64, provider string)`（用命名类型 `loginHook` 统一 9 处调用点）：`login_flow.go` 传 `auth.ProviderGitHub`，`email_flow.go` 传 `auth.ProviderEmail`；
2. `SecurityGate` 新增 `NoteLoginSuccess(userID int64, provider string) error`：直接 `audit.Record(AuditLoginSuccess, userID, provider, "", "{}")`，**不走** `g.record()`；provider 过白名单（`github`/`email`），非法值返回错误；
3. `audit.go` 常量集加 `AuditLoginSuccess = "login_success"`；
4. 装配层抽 `newOnLoginHook(checkIn, noteLoginSuccess, logger)`：**审计先行、签到在后，两者互不短路**（v0.6.0 的「签到失败即 return」会让 login_success 跟着丢，人次被系统性低估）；
5. **fail-open 边界（ADR-064 必写）**：login_success 是登录成功**之后**的事后统计事件，不适用「队列满拒绝认证动作」——`Record` 失败只 `logger.Warn`，**绝不回滚已完成的登录**；既有失败/撤销类事件的 fail-closed 语义不变；
6. 迁移 0011：`CREATE INDEX idx_auth_events_event ON auth_events(event)`——按 event 计数避免全表扫（`CountAuthEvents` 已有，零新查询代码）。

### 4.3 峰值采集（stats_daily）

> **修订（2026-11-22 团队裁决）**：原稿「读 `presence.Online()` → `UPSERT MAX`」会把采样误差写进
> 对外数字；「读 `presence.Peak()`（进程峰值）」更糟——它不按天重置，昨日 50 人同时在线会让今天
> 首个 tick 把 50 写进今日行，且被 `MAX` 锁死一整天。定稿：采样器**自持当日峰值**，只采 `Online()`。

1. 迁移 0011：`CREATE TABLE IF NOT EXISTS stats_daily (local_date TEXT NOT NULL PRIMARY KEY CHECK (GLOB 形状), peak_online INTEGER NOT NULL DEFAULT 0 CHECK (peak_online >= 0), updated_at INTEGER NOT NULL DEFAULT 0 CHECK (updated_at >= 0))`——`local_date` 语义与 `daily_checkins` 一致（`MOTD_DISPLAY_TIMEZONE`，ADR-046）。**`TEXT PRIMARY KEY` 在 SQLite 允许 NULL 且允许多行 NULL**，`NOT NULL` 与形状 CHECK 是必需防线；
2. **cmd 层 30s ticker**（照审计 ticker 模式；presence 包零改动、只读 `Online()`）：
   - 状态只有四项：`day` / `dayPeak`（当日自持峰值，跨天归零）/ `rowWritten` / `writtenPeak`；
   - **当日首 tick 无条件写一次**（值可为 0）：这是「该日存在观测窗口」的来源，也是 `--` 与 `0` 的唯一判据；
   - 之后只在峰值变高时写；跨天重置且**不做**跨日收尾写；
   - 写经 `Writer.Submit`，**单条幂等 upsert**：`ON CONFLICT(local_date) DO UPDATE SET peak_online = MAX(...), updated_at = CASE WHEN 变高 THEN excluded.updated_at ELSE 原值 END`（`Submit` 失败含「commit 结果未知」，只有幂等语句能安全重放）；
   - 失败：`logger.Warn`（当日首次）+ 其后 `Debug`，状态不推进 → 下轮自然重试；恢复时 `Info` 一条；
3. 停机补采一次（独立 2s ctx），否则「最后一次 tick 到进程退出」之间的峰值会丢；
4. 进程重启后从当前在线值继续累计（历史值已在库）；当天进程未运行的时段不可观测——诚实口径，输出文案标注起点（§4.4）。

### 4.4 展示（`/stats` 命令）

- **进程级命令**（`handle` 加 `case "stats"`，照 `/karma` 模式）：输出走安全渲染逻辑（`writeEgg` 的实现抽为 `writeSystem` 公用 helper，`writeEgg` 保留为薄封装）；
- 数字全部来自 DB 聚合与 presence 内存，**无任何用户文本**，无信任域风险；
- 注册表：`{Name: "stats", Usage: "/stats", Summary: "论坛统计（在线/登录/注册）", MaxArgs: 0}`（普通组，所有人可见含访客）；

## 9. 修订记录（2026-11-22 团队裁决）

> 本节记录实施期发现的「计划与代码事实不符」及裁决结论。历史段落已就地修订并保留"为什么改"，
> 便于下一个读计划的人不必重走一遍判断。

| # | 原计划表述 | 实际结论 | 为什么（判据） |
| --- | --- | --- | --- |
| 1 | §3.2 DoD 1「归档版块主题不出现（含 `/dev/null`）」 | 改为三态可见性：已解锁用户**可见** `/dev/null`，归档普通版块三态皆不可见 | `/dev/null` 是 `status='archived'` 的彩蛋版块，可见性由 `user_node_unlocks` 按用户决定；用户能点进去读的版块，主题必须出现在「全论坛最新」，否则可见性口径分裂。照原 DoD 验收会把正确实现判成不合规 |
| 2 | §3.1 `JOIN nodes … n.status='active'` | 改为 per-user allow-list（`node_id IN (...)`） | JOIN 会挡掉已解锁 `/dev/null`（archived）；放宽 status 又会让归档普通版块泄漏。白名单是唯一能同时满足两侧的口径 |
| 3 | §3.1 `SELECT t.*` | 改为逐列显式投影（`t.id, t.node_id, …`） | `threads` 自 0004 起 8 列，`scanThread` 只扫 7 列，`t.*` 会运行期报「expected 7 destination arguments」 |
| 4 | §3.1「索引即可覆盖跨版块」 | 追加 `INDEXED BY` 强制命中 + 行值游标 `(last_reply_at, id) < (?, ?)` | 实测不加提示时同一 SQL 在不同数据分布下选不同索引（含 TEMP B-TREE）；OR 形态即使有索引也只能 SCAN，深翻页 O(k×N) |
| 5 | §3.2 DoD「无新 ViewModel 字段」 | 补记新增查询契约 `AllowedNodeIDs`、`ErrInvalidNodeID` | 白名单必须从入口层语义（已解锁节点）传进用例层，属查询契约而非 ViewModel 契约 |
| 6 | §4.2 `gate.Record(...)` | 新增 `SecurityGate.NoteLoginSuccess(userID, provider)` | `SecurityGate` 无导出 `Record`，且 `record()` 固定用 `g.provider`（恒为 github），会把邮箱登录记成 github |
| 7 | §4.3 读 `presence.Online()` 采样 | 采样器**自持当日峰值**（`dayPeak`，跨天归零），**不读** `presence.Peak()` | 进程峰值不按天重置：昨日 50 人同时在线会让今天首个 tick 写 50，并被 `MAX` 锁死一整天；基线减法同样抵消（`Peak() ≥ base` 恒成立） |
| 8 | §4.3 每 30s 一次 UPSERT | 只在「当日首 tick / 创新高」时写 | 2880 次/天的事务对写队列是纯负担；首 tick 仍**无条件**写（0 也要写），否则「跑了一整天没人来」会显示成「没有观测」 |
| 9 | §4.4 文案草稿缺「昨日在线峰值」 | 补回该行（v3 定稿第 4 行） | §0/§4.1 已拍板「昨日在线人数 = 昨日峰值在线」；不补则该指标会被实现、被测试、写进 ADR 却不上屏 |
| 10 | §4.4 `StatsReader` 峰值类返回 `int` | 改为 `(int, bool, error)` | 无行必须能与「观测到 0」区分，否则进程未运行的整天会被显示成「今天没人」 |
| 11 | §4.4 文案「今日峰值在线 / 历史最高在线」 | 改名「今日在线峰值 / 历史在线峰值」 | 原语序断句落在「今日峰值／在线」；「最高」是绝对化措辞，而该值自 v0.7.1 起才累积 |
| 12 | 未定义 | `--` 判据定为两条件：该日无行 **且** 当前在线为 0；展示层钳制今日 ≥ 当前在线、历史 ≥ 今日 | 实时在线数本身构成观测；否则会出现「今日在线峰值 `--` · 当前在线 3」与「峰值 5 · 当前在线 6」这类自相矛盾的屏 |
| 13 | 未定义 | 明确**不**保证「同日多次渲染今日峰值单调不降」 | `Online` 在两次 tick 之间会动、日内峰值只在 tick 时前推；要单调必须渲染路径写回，属禁止机制 |
| 14 | 未定义 | `stats_daily.local_date` 加 `NOT NULL` + 形状 CHECK，`peak_online`/`updated_at` 加 `>= 0` | SQLite 的 `TEXT PRIMARY KEY` 允许 NULL 且允许多行 NULL，一次空日期即污染全历史 `MAX`；`length=10` 挡不住 `2026/11/22` |
| 15 | 未定义 | `onLogin` 装配置于 `newOnLoginHook`：审计先行、签到在后、两者互不短路 | v0.6.0 的「签到失败即 return」会让 login_success 跟着丢，累计登录人次被系统性低估且永不报警 |
